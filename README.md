# Xlam Connect

Приватная виртуальная сеть в духе Radmin VPN / Hamachi: друзья заходят в «комнату» по названию и паролю, получают
виртуальные IP (`10.26.x.x`) и видят друг друга как в одной локалке — игры по LAN, общие папки, RDP, ping.

## Как это устроено (по-настоящему)

```
 Игра/Windows ──► адаптер Wintun ──► Engine ──┬── UDP напрямую (hole punching, P2P)
                                              ├── UDP через сервер (relay, если NAT строгий)
                                              └── TCP к серверу координации (список игроков, IP, адреса)
```

* **Сервер** (`server/server.js`, 0 зависимостей): авторизация в комнате, выдача постоянных IP, обмен адресами,
  STUN-подобное определение внешнего IP:порта, relay-резерв. Трафик он **не может прочитать**.
* **Шифрование**: X25519 между игроками + пароль комнаты подмешивается в ключ (HKDF) → ChaCha20-Poly1305,
  защита от повторов и подмены. Даже злонамеренный сервер не расшифрует трафик и не подставит ключи без пароля.
  Сервер хранит лишь производную `authKey`, не пароль.
* **NAT**: пинги на все кандидаты (внешний + LAN адреса) одновременно; прямой канал выбирается автоматически,
  иначе трафик идёт через relay и сам «апгрейдится» до прямого, когда пробой удаётся. В списке видно: Напрямую / Через сервер, пинг.
* **LAN-игры**: broadcast и multicast пакеты рассылаются всем в комнате; входящие проверяются на подделку IP-источника.
* Авто-переподключение, чат, трей, правило брандмауэра только для адаптера Xlam, автозапрос прав администратора.

## 1. Запустить сервер (нужен один раз, на VPS с белым IP)

```bash
node server/server.js --port 7777          # открыть порт 7777 TCP **и** UDP
# или Docker:
docker build -t xlam-server server && docker run -d --restart=always -p 7777:7777/tcp -p 7777:7777/udp -v xlam:/data xlam-server
```
Подойдёт любой VPS за ~3–5 $/мес (или домашний ПК с пробросом порта 7777 TCP+UDP). Параметры: `--subnet`, `--max-peers`, `--relay-mbps`.

## 2. Собрать приложение (Windows)

Вариант А — двойной клик по `build-windows.bat` (нужен Node.js 20+). Результат в `dist\`: установщик и portable `.exe`.
Вариант Б — залить проект на GitHub: workflow `.github/workflows/build.yml` соберёт `.exe` сам (вкладка Actions → Artifacts).

Запуск без сборки: `npm install && npm start` (запросит права администратора — они нужны для создания адаптера).

## 3. Пользоваться

«Создать сеть» → название, пароль, адрес сервера → «Скопировать приглашение» → отправить друзьям → они жмут «Войти в сеть».

## Проверка

`npm test` — сквозные тесты движка: создание/вход, прямой путь, relay, неверный пароль, подмена IP, broadcast,
чат, переподключение после обрыва сервера.

## Ограничения

* Только IPv4, Windows x64 (Wintun). Движок кроссплатформенный, нужна лишь реализация TUN для Linux/macOS.
* Для строгого (симметричного) NAT трафик идёт через сервер — скорость ограничена каналом сервера (`--relay-mbps`).
* Игры, которые ищут лобби через 255.255.255.255, иногда требуют выбора адаптера в настройках игры.
